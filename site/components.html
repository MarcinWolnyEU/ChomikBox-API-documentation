chomikbox.exe - the application

Kind
Qt 4 GUI, 3.9 MB, 32-bit, MSVC. image base 0x400000, SHA-256 13A500DE0C270D289C30D772283FD332D4B427D196C80F0B166D8C53762A6386.
Launched by
Start menu, Desktop and Quick Launch shortcuts; the HKCU\…\Run value; the MSI finish page; Explorer verbs and chomik:// URLs; the updater after an update; the browser plug-in when ChomikBox is not running.
Reads
base.ini, conf.ini, the queue files, skins, animation packages, translations, tsplugins\integration\*.tsp.
Writes
conf.ini, queue-upload-<id>.ini, queue-download-<id>.ini, playlist.m3u8, message.log (rotated into backup\), the player cache and thumbnails, minidumps; registry: autostart Run value and music file associations.
Talks to
box.chomikuj.pl (SOAP), file servers, the update repository; starts installer.exe and crashsender.exe; receives commands on the named pipe.

The main executable holds every user-facing module: the side panel, the Dodawanie (upload), Pobieranie (download) and Muzyka (music) windows, the folder and file windows, settings, the desktop hamster, the tray icon and notification balloons. It also contains the SOAP client, the UUpdater update client, the BrowserIntegrationManager that installs the browser plug-in, and a Google Breakpad exception handler. Structure and layers are described on Architecture.

It embeds a single Qt resource tree with four uncompressed files: :/default/defconf.ini (62 841 bytes) and the brand overlays defconf-lolabits.es.ini, defconf-chomikuj.pl.ini and defconf-minhateca.com.br.ini. Observed

Command line and remote commands

The same parser, Application::executeRemoteCommand, handles the process's own command line and commands that arrive over the named pipe from a second launch or the browser plug-in. A value may follow its switch directly, as in -d<url> or -u"%1". Observed in the client, the MSI registry rows and the plug-in.

chomikbox1conf.exe - 1.x importer

Kind
Qt 4 GUI, one-shot migration wizard (main class ChomikBox1). Imports only QtCore4 and QtGui4, so it has no network classes.
Launched by
MSI custom action ExeCaKeyF01: "[SystemFolder]Cmd.exe" /c "start /b chomikbox1conf.exe", condition not Installed, sequence 6603 (after InstallFinalize). The action runs on a fresh install and on a major upgrade (a package with a new ProductCode and the same UpgradeCode), because the condition does not test for an upgrade. It does not run on a repair, on a minor update that keeps the ProductCode, on uninstall or on in-app updates. Inferred from the installer tables (not run)
Reads
%APPDATA%\ChomikBox\config.xml, upload queues filequeue.chq / filequeue_*.chq, leftovers CHR*.tmp, resume data, the 1.x player cache.
Writes
conf.ini, queue-upload[-<hamsterId>].ini, the key player/chomikbox1-cache.
Switches
--ask, --force (see below), one positional argument that the import never uses, plus the framework options.

The wizard asks Import settings from ChomikBox 1.x? and offers three check boxes: settings, existing accounts and cache. Errors include Configuration is NOT valid XML ChomikBox 1.x file. Observed

The two switches were first read the wrong way round. The constructor sets --force at offset +0xa8 and --ask at +0xa9, and --force never skips a confirmation. Observed

When the importer asks (after a valid 1.x config.xml was read)
2.x conf.iniFlagBehaviour
existsnoneNo dialog, nothing imported, the program quits
exists--forceAsks New settings already exists. Import settings from ChomikBox 1.x and overwrite new one?; only Yes imports
missingnoneNo dialog; imports at once with all three boxes (settings, accounts, cache) ticked
missing--askAsks Import settings from ChomikBox 1.x? with the three boxes; only Yes imports

The MSI starts the program without arguments, so a fresh install imports silently when no conf.ini exists, and an upgrade over an existing conf.ini does nothing. Inferred The resume record of a 1.x direct upload is a CryptoAPI-decrypted blob whose lines (at least seven) carry the local path, a size, the folder id, stamp, token, host and port; it is not a delimited record. The string 192.168.10.30 is never used, so it is not a contacted host. Observed

The 1.x config.xml keys it understands include MaxUploadSpeed, Folder, Autologin, Remember, Volume, MaxPlayerCacheSize, DefaultFileAssocs, userinfo-%1, password-hash and password-len. Observed

Rebuilding 1.x upload URLs

One function splits each 1.x queue line (at least seven fields), normalises \ to / and fills this template:

http://%1:%2/file/?token=%3&stamp=%4&folderId=%5&fileName=%6
       host port      token    stamp    folderId    fileName

The result goes into the 2.x queue item's directUrl, so that unfinished 1.x uploads can resume in 2.x. Inferred The importer itself cannot send the request; the request method and body are Unknown here.

The string table also contains the private address 192.168.10.30, apparently an internal test host. Its purpose is Unknown.

crashsender.exe - crash reports

Kind
Qt 4 application, “Crash sender version: 0.4” (--version).
Launched by
The Breakpad callback in chomikbox.exe, through ShellExecute on <applicationDirPath>/crashsender.exe.
Inputs
The minidump and the paths of message.log, conf.ini, both queue files and the playlist, plus the account id and name.
Talks to
POST http://bts.box.chomikuj.pl:8088/crash. It ignores the reply: only QNetworkReply::error() is used, the body, status code and headers are never read. There is no retry, and the process always quits after the first reply or error. In GUI mode a network error shows an Error occured box; with --no-gui it is only written to the debug output. Observed 
crashsender.exe [--no-gui] chomikbox <version> <arch> <minidump> <message.log> <conf.ini>
                <uploadQueue.ini> <downloadQueue.ini> <playlist.txt> <chomikId> <chomikName>
crashsender.exe [--no-gui] chomikfile <version> <arch> <minidump> <serverIds> <settings.xml> <message.log>
crashsender.exe --version

The <arch> argument is the constant win32, which is also the platform default of the update repository. Observed The second form belongs to a sibling product, chomikfile. In GUI mode and for project chomikbox the user is asked first: Crash has been detected in application. … Do you want to send debugging information? With --no-gui, or for chomikfile, the report is sent at once. chomikbox.exe passes --no-gui when an internal flag is set; what sets that flag is Unknown.

Request format

QNetworkAccessManager::post() with Content-Type: multipart/form-data; boundary=<B>. The boundary is the current time formatted as CSddMMdyyhhmmsszzz. No other custom headers are set. Text parts declare quoted-printable but carry raw UTF-8, and their Content-Disposition line ends in a stray ; . Observed

chomikbox
--<B>

Content-Type: Application/Octet

<raw file bytes>
…
--<B>--

installer.exe - updater and plug-in installer

Kind
Qt 4 GUI “Updater 0.4.2”. installer.exe and installeru.exe have identical code (160 256 bytes each); the 1 122 differing bytes are the manifest (requireAdministrator vs asInvoker) and the PE header fields that follow from it.
Launched by
chomikbox.exe: UUpdater::doUpdate through BProcess::runAsAdministrator, and BrowserIntegrationManager for --plugmode. The client never names either file for updates. It starts the staged file of the package entry marked updater="exec" whose privileges equal the client's compiled-in constant admin. BProcess::runAsAdministrator reads that file's embedded manifest and calls ShellExecute with the verb runas when it says requireAdministrator, otherwise open. So installer.exe is elevated, and installeru.exe (asInvoker) would not be. Which of them a repository nominates is data in packages.xml. Observed mechanism, Unknown repository content
Switches
--install, --uninstall, --plugmode, --set-dist <dist>, --version.
Writes
Program files from the package, registry (below), browser plug-in folders, and base.ini (title, domain) only when the system clock is earlier than 2012-01-01, so in practice never.

Update mode

The updater reads packages.xml from the staging directory and processes each item: Removing directory/file, Installing file (copy or symlink) and Executing command (through QProcess). Guards such as Forbidden file operation on %1 and … skipped due to previous errors apply, and crashsender.exe and packages.xml get special handling. It does not check the package before copying or running anything. Its only content check is a SHA-1 of the installed files against the sha1 attributes of the new packages.xml, after the copy, and the result only decides whether the package gets an installed status: no error message, no rollback. The digest of the work list that the client passes as an argument is stored but, as far as observed, not used. Afterwards it restarts chomikbox.exe --update=success or --update=failed. Observed C-07

On the client side UUpdater fetches from http://bts.box.%1/repo/dists (also http://download.box.%1/updates), follows redirects, parses packages.xml, unpacks gzip packages, compares the SHA-1 of every file (of the decompressed content for .gz) with the sha1 attribute of packages.xml and stages everything in <tmp>/chomikbox.tmp/. A mismatch is reported as Signature error, but no signature or key exists: the hash comes from the same unauthenticated HTTP channel as the file, and packages.xml itself is not verified at all (C-07). Observed packages.xml attributes the client understands: sha1, size, source, privileges, updater, restart, offline, gzSize, target, symlink, files-to-copy, do-update, priority, changes, changelog, originalFileName, optional, extra. admin is not an attribute but the value the client compares privileges with. Observed

Plug-in mode

installer.exe --plugmode --install tsplugins/integration/ <browser dir> (or --uninstall) copies or removes npcbplugin.dll in a browser's plug-in folder. On failure it suggests closing the browser first or logging in with administrator rights. Observed

Registry written by the updater

  • HKLM\SOFTWARE\ChomikBox (default) = <directory of the running updater>\chomikbox.exe, written as REG_SZ in the 64-bit registry view (KEY_WOW64_64KEY, not Wow6432Node). This is the value the browser plug-in reads for a cold start. The MSI is a 32-bit package and writes only the 32-bit view, so a plain MSI install has no such value; on the analysed machine the 64-bit key does not exist. Observed
  • HKCR\chomik\shell\open\command, chomik\DefaultIcon and Software\Classes\ChomikBox.MusicFile.<ext>\DefaultIcon are re-pointed to the new exe path. Observed

chomikbox_win7.tsp - taskbar plug-in

Kind
PE32 DLL with a custom extension; exports tsbox_plugin_handle and tsbox_plugin_qt_build. Classes: ChomikboxWin7Integration, Plugin, SlotReceiver.
Launched by
Loaded by chomikbox.exe from tsplugins/integration/ with QLibrary, after a Qt build check (Plugin unload failed! on error).
IPC
None beyond in-process Qt signals and slots.

The plug-in sets the AppUserModelID fsfilesolutions.chomikbox, registers the TaskbarButtonCreated message, hooks the GUI thread with SetWindowsHookEx and uses ITaskbarList3 to add a thumbnail toolbar (previous, play/pause, next) built from the Qt style's standard icons, plus a taskbar progress state. Its SlotReceiver listens to uploaderStatusChanged, uploaderStartWork, uploaderFinishedWork, uploaderPaused and the matching downloader signals, and calls the player slots playPreviousSong(), togglePlay() and playNextSong(). Observed

npcbplugin.dll - Click Catcher

Kind
NPAPI plug-in (NP_GetEntryPoints, NP_Initialize, NP_Shutdown). Version resource: “ChomikBox Click Catcher Plug-In for Netscape, Opera, Mozilla, Chrome”, FileVersion 0.0.9, internal name npcbgeckoplugin.dll.
Launched by
Loaded by browsers from their plug-in folder after installer.exe --plugmode --install.
Talks to
The running chomikbox.exe over the named pipe, or starts it with ShellExecute.

The plug-in claims the MIME types of downloadable files. When a browser would download one, it hands the stream to the plug-in, which copies the stream URL and starts a worker thread. Inferred from NPP_NewStream. The 31 distinct MIME types (32 entries, audio/x-mpeg twice):

application/x-msdownload application/x-compressed application/zip application/octet-stream application/x-zip-compressed application/arj application/rar application/x-tar audio/mpeg audio/x-mpeg audio/mp3 video/msvideo video/x-msvideo video/mpeg video/x-mpeg video/quicktime application/x-rar-compressed application/x-msdos-program audio/x-ms-wma video/divx video/x-ms-wm video/x-ms-wmv video/x-ms-wmx application/x-7z-compressed application/msi application/exe application/x-exe application/dos-exe application/x-winexe application/msdos-windows application/metalink+xml

How the URL reaches ChomikBox

  1. ProcessIdToSessionId(GetCurrentProcessId()) gives the session id; the pipe name is \\.\pipe\qtsingleapp-Chomik-739b-%d.
  2. CreateMutexA(NULL, TRUE, "ChomikBox2"). If it already exists, ChomikBox is running: the plug-in opens the pipe, waiting up to 2000 ms with WaitNamedPipeA if it is busy, and writes a QDataStream frame: a big-endian length of strlen(url) + 3, then -d, the URL and a NUL.
  3. Otherwise it runs ShellExecuteA(NULL, "open", <path>, "-d<url>", …), with the path read once at plug-in load from the default value of HKLM\SOFTWARE\ChomikBox in the 64-bit registry view (the DLL is 32-bit but asks for KEY_WOW64_64KEY). If the key or its default value is missing, the path is empty. The ShellExecuteA result is not checked and this path shows no message box.
  4. Failures show a message box titled ChomikBox Browser Plug-In.

A dead path today

Chrome (version 45, 2015), Opera (37) and Firefox (52, 2017) removed NPAPI support, so current browsers never load this plug-in. Inferred On a plain MSI install the cold start would also be a silent no-op: the 64-bit key does not exist (the MSI writes only WOW6432Node), the path is empty and ShellExecuteA fails unnoticed. Observed registry state, Inferred result (nothing was executed). chomik:// links and the Explorer verbs remain working ways into the app.

Skins - skins\app\*.skin

All of .skin, .hintskin, .anim and .tur are Qt 4 external resource files produced by rcc -binary: the magic bytes qres, version 1, big-endian offsets to the tree, data and names, 14-byte tree entries and optional zlib blobs. They are registered at run time with QResource::registerResource(). Files of the same name inside one archive are locale variants, chosen by QLocale::Language (90 = Polish, 31 = English, 96 = Russian, and so on). Observed

  • green2.skin (2.1 MB, 473 files, Zielony Chomik, Green Hamster) is the default; green.skin (1.0 MB, 319 files) is the default for Russian.
  • Contents: 9-slice window art (dialog.png, window.png, frame.png), a Qt style sheet per window, tray animation frames, per-state button images (.hover, .pressed, .on, .disabled), images with captions baked in per language (lang90 and so on), descr.ini and chomikbox.ico.

The panel's Dodawanie (Upload) tile is stored in green2.skin as four state images (normal, hover, pressed, on = module open) plus a caption-less variant whose text the application draws; the Polish captions are baked into the other images. The picture above is an illustration, not the skin's artwork.

Balloon skins - skins\hint\*.hintskin

Eight notification-balloon skins of ten files each: a Qt Designer form (notificationhintwidget.ui), a style sheet, four bubble images whose tail points to a different corner, window and frame images and a close button. simple is the default, green the default for Russian. The other six carry the names of white-label brands that share this client: Abelhassimple, Abresesamosimple, Lolabitssimple, Minhatecasimple, Toutboxsimple and Tuttoboxsimple; the last two are byte-identical. Observed

Animations - files\anim\*.anim

21 packages drive the desktop hamster (class Animation, config section [animation]): pacidle, pacidle0–9, pacidlestart1–3, pacmainidle, paccharacter, pacdragfile, pacdropfile, pacmusic, pacscreenshot and pactyping. Each holds an XML state machine and frame pairs: a 256×256 colour JPEG plus a greyscale alpha-mask JPEG, 2 103 pairs in total. The XML lists conditions (idle, file-over, file-drop, player-playing, screenshot, typing, mousePress) and transitions (<way start stop enter exit prob priority>). Observed

Illustrations of the animation states, drawn for this site; they are not frames from the packages (those are 256×256 colour JPEGs).

Tutorial - locale\tutorial.tur

A qres file with seven entries, all named chomikbox, one per locale: default (English), Polish, Italian, Spanish, Russian, Portuguese and Brazilian Portuguese. Each is zlib-compressed UTF-8 in a small wiki-like markup: [[page-id|Title]] headers (welcome, help:add_files, help:play_music, help:downloader, …), {{go:<page>|label}} and {{skip|label}} buttons, inline HTML, and a trailer ## vim: ft=tutorial. The hamster speaks in the first person: drag it … directly into my hands. Controlled by [tutorial] enabled, module-info-show and welcome-info-show. Observed

Translations - locale\*.qm

The source language of the UI strings is English. pl.qm has 656 messages, 618 of them translated; en.qm has 670 and overrides 102. Together they cover 42 contexts, one per Qt class. locale\qt\qt.pl.qm is Qt's own Polish catalogue for the standard dialogs. Observed

base.ini - brand bootstrap

Four keys in [main]: domain (chomikuj.pl), title and name (both ChomikBox) and an integrity key. The domain picks the brand overlay and the server names; the title names the data folder; the name is QCoreApplication::applicationName, which is also the name of the Run value. The installer rewrites it only when the system clock is earlier than 2012-01-01, so in practice never. Details: Configuration. Observed
